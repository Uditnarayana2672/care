# Decisions & deviations

| # | Decision | Why |
| - | -------- | --- |
| 1 | **Hindsight client verified against docs** (`hindsight-client`, `Hindsight`, `acreate_bank`, `aretain`, `aretain_batch`, `arecall`, `areflect`, `alist_memories`, `acreate_directive`, `acreate_mental_model`, `arefresh_mental_model`). `metadata` is `dict[str,str]`, so every metadata value is stringified. Directives and mental models use the client helpers (no need for the generated namespaces). | Followed the docs over the prompt where they differ. |
| 2 | **Local memory backend** (`LocalBackend`, `local_memory` table) is used when `HINDSIGHT_API_KEY` is empty. Same `MemoryService` interface; recall is token overlap, observations are consolidated from a `pattern` metadata key. | The build environment had no Hindsight key and no network guarantee; the demo must run offline. With a key set, the real Hindsight backend is used and consolidation is done server-side. |
| 3 | **Rule-based agent driver** when `GROQ_API_KEY` is empty (and as fallback when the LLM fails twice / returns invalid tool args). It calls the *same* tool functions as the LLM loop. | Same reason; also guarantees chat never hard-fails. |
| 4 | **SQLite + in-process pub/sub/cache** fallback when `DATABASE_URL` is sqlite / `REDIS_URL` empty; the scheduler then runs inside the API process. Docker compose uses Postgres 16 + Redis 7 + a separate worker as specified. | Docker, Postgres and Redis were not installed where this was built, so the Postgres/Redis path is **untested here** (models use portable `Uuid`/`JSON` types; Alembic migration was generated and applied on SQLite). |
| 5 | **Commit-before-retain.** `MemoryService.retain_fact` commits the caller's session first. | Implements "write PostgreSQL first, then retain" and avoids SQLite writer locks. |
| 6 | `log_care` tool **queues drafts**; rows are written when the caretaker confirms ("Save all"). The confirm click carries the drafts back to `POST /chat` (`action=save_logs`) and the server re-validates assignment per entry. | Matches W4 (confirmation card) without server-side draft state. |
| 7 | Reasons for "Refused"/"Other" get optional detail chips (e.g. "Feels cold") so W7 can cluster reasons. Free typing also works. | Reason text is what makes the observation useful. |
| 8 | Seed users/patients get deterministic UUIDs (uuid5 of email / patient code). | Sessions and URLs survive `make demo-reset`. |
| 9 | shadcn/ui: the UI is a direct port of `carebridge-ui.html` CSS tokens into `globals.css` with small hand-written primitives instead of generated shadcn components. | Keeps pixel parity with the reference design. `lib/api-types.ts` is generated by `openapi-typescript`; routes return plain dicts so response types are in `lib/types.ts`. |
| 10 | `/me/events` uses `EventSource` (check-ins, board changes); `/chat` is POST so it is consumed with `fetch` streaming (EventSource cannot POST). | Browser API limitation. |
| 11 | Todo category for fluids/diet is `meal` (enum in §5 has no `diet`). | Schema fidelity. |
| 12 | Hint extraction from mental models (W9) is keyword-based over observation text. | Cheap, deterministic, cached; refreshed nightly and on new patterns. |
